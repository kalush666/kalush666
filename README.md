## 🛰️ Flagship Project — SMART

> **SMART** — *Simulation and Management for Advanced Reconnaissance and Tactical operations*
> A microservices platform for **UAV simulation, live telemetry ingestion, and mission/assignment** — with a **genetic algorithm** at the core of the assignment engine.

<div align="center">

[![SMART Org](https://img.shields.io/badge/Explore_the-SMART_Organization-512BD4?style=for-the-badge&logo=github&logoColor=white)](https://github.com/SMART-PROJECT-SMART)

</div>

**What it does**
- 🛩️ **UAV simulation** — multi-aircraft physics, flight paths, Quartz-scheduled telemetry, ICD-aligned semantics
- 📡 **Live telemetry pipeline** — SharpPcap sniffing → validate → decode → output, dynamic ports & devices
- 🧠 **Mission & assignment** — async suggestion queue, apply-assignment execution, and a **genetic algorithm** assignment engine with a large automated scenario/stress test surface
- 🗂️ **Durable records** — mission-scoped telemetry & assignment history on MongoDB
- 🔔 **Event-driven coordination** — DeviceManager as fleet authority, webhooks + Kafka keeping every service aligned
- 🗺️ **Operator UI** — Angular SPA with map-based assignment review, live view, device management, and archive investigation

**Architecture at a glance**

| Service | Role |
|---|---|
| **Simulator** | UAV flight simulation, Quartz scheduling, ICD telemetry |
| **Telemetry-Device** | Live capture / decode / validate pipeline |
| **DeviceManager** | Authoritative UAV & sleeve store, outbound webhooks |
| **ACM** | Assignment & sleeve-side orchestration, Kafka status |
| **Mission-Service** | Assignment suggestions, execution, genetic algorithm |
| **LTS** | Kafka-backed live telemetry snapshots & wanted-fields |
| **Telemetry-Records** | Historical / mission-scoped telemetry & assignments |
| **Mongo-Consumer** | Event-driven persistence worker |
| **Core** | Shared models + ICD telemetry definitions |
| **Client** | Angular operator UI |

**Stack:** .NET 9 · Apache Kafka · MongoDB · Angular · SignalR · Quartz.NET · Docker Compose · Nginx · Genetic Algorithm

```
UI ──▶ Mission / Telemetry-Records / LTS / Simulation
DeviceManager ──(webhooks)──▶ Simulation · Telemetry-Device · ACM · Mongo-Consumer
ACM · LTS · Mongo-Consumer ──▶ Kafka
DeviceManager · Mission · Telemetry-Records · Mongo-Consumer ──▶ MongoDB
```

## 💡 How I Build

**Architecture & design**
- Clean architecture — thin controllers, services own workflows, repositories own I/O
- SOLID, design patterns, and explicit DTO / entity boundaries
- Microservices, event-driven integration (Kafka + webhooks), API-first design
- Meaningful naming, no inline comment noise — the code should read itself

**Practices**
- Async patterns (C# Channels, BackgroundService, webhook-based async REST)
- Performance benchmarking and optimization (the SMART assignment engine beats baseline approaches by orders of magnitude)
- Documentation-driven development and UML/Mermaid diagrams
